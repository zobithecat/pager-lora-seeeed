# `!CAR` — 차량 상태 비콘  (PROTOCOL.md §5 추가 제안)

> 정본 스펙은 `gopher-over-lora/lora/PROTOCOL.md`다. 이 문서는 거기 §5 L1 레지스트리에
> 들어갈 **minor(하위호환) 추가**의 초안이고, 현재 구현은 `pager-vehicle/`(P01) 하나뿐이다.
> 모르는 `!` 타입은 조용히 버려지므로(v1.3 forward-compat) 기존 노드는 영향이 없다.
> 정본에 병합할 때 버전을 올리고(§12 changelog) 이 파일은 그쪽을 가리키게 바꿀 것.

## 프레임

```
!CAR\t<id>\t<st>\t<t_c>\t<rh>\t<hpa>\t<vbat_mv>\t<up_s>\t<nbr>
```

| field | 의미 |
|-------|------|
| `id` | 차량 노드의 3자 routing id (`P01`). 봉투 `src`와 같다 — `!FS`/`!RS`와 같은 관례로 본문에도 싣는다 |
| `st` | 상태 토큰. **첫 글자** `P`=주차(자체 배터리 구동) / `D`=주행(차량 전원 있음). 뒤따르는 글자는 플래그: `H`=실내 과열(기본 ≥ 60 °C, LiPo 위험). 수신자는 **모르는 플래그 글자를 무시**해야 한다 |
| `t_c` | 실내 온도 °C, 소수 1자리 (`-12.3`). 센서 없음 = `-` |
| `rh` | 상대습도 %, 소수 1자리. 센서 없음/BMP280 = `-` |
| `hpa` | 기압 hPa 정수. 없음 = `-` |
| `vbat_mv` | 배터리 전압 mV. 측정 배선 없음 = `-` |
| `up_s` | 부팅 후 초. 리셋되면 재부팅한 것 |
| `nbr` | 이 차가 지금 직접/간접으로 듣고 있는 노드 수 (discovery 테이블 크기) |

전체 ≤ 60 B (§5 line budget). 최악의 경우 약 46 B.
새 필드는 **뒤에만** 추가한다 — 수신자는 앞의 9개만 읽고 나머지는 무시.

## 규칙

- **L1, beacon-class (§8a).** 주기적 unsolicited 프레임이므로 스트림 announce(`!GR`/`!BR`/`!VA`)에
  양보하고, 자기 주기 1회를 넘겨서까지 미루지는 않는다.
- **ttl = `RELAY_TTL_MESH` (3).** 주차장의 차는 대개 건물 안 수신자의 직접 범위 밖이다.
  relay를 못 타면 비콘의 존재 이유가 없다. 따라서 수신측 hop 해석(§10)이 유효한 타입이다.
- **주기: 주차 중 300 s + 0–10 s 지터, 주행 중 off.** 봉투 포함 ~65 B ≈ 0.45 s ToA(SF9, CR 4/6) →
  5분 주기면 relay 2홉을 다 타도 채널 점유 약 0.5 %. 주기를 60 s 아래로 내리지 말 것 (`!RS`의 ≥ 120 s와 같은 이유).
- **상태 전환 시 1발.** `D→P`(주차 시작, 15 s 뒤)와 `P→D`(출발, 5 s 뒤), 그리고 `H` 플래그가
  새로 섰을 때는 주기를 기다리지 않는다. 이 단발의 §8a 양보 상한은 60 s.
- **discovery와는 별개.** 차량 노드도 엔드포인트이므로 `HB`(ttl=1, 60 s)는 역할과 무관하게
  계속 낸다. 이웃 테이블은 `HB`로, 원격 상태 확인은 `!CAR`로.
- **송신 프로파일은 legal (§2).** 실외·무인 노드다: EIRP ≤ 14 dBm, 모든 TX 전에 LBT(CAD).

## 수신측

- 채팅(L2)에 절대 섞지 않는다. 노드 테이블의 상태 칸을 갱신하는 용도.
- `st`에 `H`가 있으면 눈에 띄게 표시할 것 — 주차된 차 안의 LiPo는 실제 화재 위험이다.
- 인증은 없다 (DOCTRINE D5). `!CAR`는 읽기 전용 텔레메트리이고 어떤 동작도 트리거하지 않는다.
